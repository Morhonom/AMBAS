## Выполнение практической работы

### Этап 1 — Теоретические основы Lua-скриптинга и каналов RC в ArduPilot

#### 1. Модель выполнения скриптов (AP_Scripting)
В ArduPilot скрипты выполняются внутри встроенной виртуальной машины Lua в отдельном низкоприоритетном потоке операционной системы реального времени (RTOS). Это гарантирует, что даже в случае задержки или ошибки в скрипте критически важные высокочастотные контуры стабилизации аппарата не будут заблокированы.

Скрипт строится на принципах многозадачности:
* В скрипте определяется функция циклического обновления ( `update()`);
* В конце функции обязательно возвращается указатель на саму функцию и таймаут в миллисекундах до следующего вызова:
  ```lua
  return update, 100 -- повторный вызов функции update через 100 миллисекунд (10 Гц)
  ```
* Если функция возвращает `nil` или не возвращает ничего, скрипт завершает свою работу.

#### 2. Отправка сообщений на наземную станцию (GCS)
Для передачи текстовых уведомлений используется `gcs`:
```lua
gcs:send_text(severity, "Текст сообщения")
```
Параметр `severity` задает уровень важности сообщения согласно стандарту MAVLink (`MAV_SEVERITY`):
* `0` — **EMERGENCY** (чрезвычайная ситуация, отказ системы);
* `1` — **ALERT** (требуется немедленное вмешательство);
* `2` — **CRITICAL** (критическое предупреждение);
* `3` — **ERROR** (ошибка);
* `4` — **WARNING** (предупреждение);
* `5` — **NOTICE** (важное штатное уведомление);
* `6` — **INFO** (информационное сообщение);
* `7` — **DEBUG** (отладочное сообщение).

Для пользовательских сообщений и статусов штатных событий обычно используется уровень `6 (INFO)` либо `4 (WARNING)`.

#### 3. Каналы радиоуправления (RC) и концепция переключателей AUX
В аппаратуре радиоуправления каналы распределяются следующим образом:
* Каналы 1–4 — основные оси управления летательным аппаратом:
  * Канал 1: Roll (крен);
  * Канал 2: Pitch (тангаж);
  * Канал 3: Throttle (газ);
  * Канал 4: Yaw (рыскание).
* Каналы с 5-го и выше — дополнительные вспомогательные каналы (AUX -- *Auxiliary*):
  * **AUX 1** = Канал RC5 (в прошивке ArduCopter по умолчанию назначен на выбор полетных режимов через параметр `FLTMODE_CH = 5`);
  * **AUX 2** = Канал RC6;
  * **AUX 3** = Канал RC7;
  * **AUX 4** = Канал RC8;
  * **AUX 5** = Канал RC9.

В рамках данной практической работы изучается работа с каналом — AUX 2 (Канал RC6).

#### 4. Методы считывания состояния тумблера в Lua
Существует два основных способа работы с каналами:
1. **Прямое считывание значения ШИМ (PWM):**
   Функция `rc:get_pwm(channel_number)` возвращает текущую длительность импульса в микросекундах (обычно от 1000 до 2000 мкс, где 1500 мкс — нейтральное положение).
2. **Использование функций переключателей ArduPilot (`RCx_OPTION`):**
   В ArduPilot каналу можно назначить функцию скриптинга (например, параметр `RC6_OPTION = 300` соответствует опции `Scripting 1`). В скрипте такой переключатель находится функцией:
   ```lua
   local chan = rc:find_channel_for_option(300)
   local pos = chan:get_aux_switch_pos() -- возвращает 0 (Low), 1 (Mid), 2 (High)
   ```

В данной работы мы используем прямой метод опроса ШИМ (`rc:get_pwm()`).

### Этап 3 — Разработка Lua-скрипта для AUX2

Откройте каталог `~/ardupilot/ArduCopter/scripts` в редакторе **Visual Studio Code**:
```bash
code ~/ardupilot/ArduCopter/scripts
```

Создайте новый файл с именем `hello_world.lua`.

#### Детектирование переднего фронта
> Если написать простое условие:
> ```lua
> if pwm > 1500 then
>     gcs:send_text(6, "hello world")
> end
> ```
> То при включенном тумблере сообщение `hello world` будет непрерывно отправляться каждые 100 мс (10 раз в секунду).
> 
> Правильное решение — реализовать детектирование переднего фронта: отправлять сообщение ровно один раз в момент перехода тумблера из выключенного состояния (`<= 1500 мкс`) во включенное (`> 1500 мкс`), сохраняя предыдущее состояние в отдельной переменной.

#### Листинг скрипта прямого опроса ШИМ канала AUX2

Наберите в файле `hello_world.lua` следующий исходный код:

```lua

-- AUX 2 соответствует 6-му каналу RC (Ch1-4: стики, Ch5: AUX1/FLTMODE, Ch6: AUX2)
local AUX_CHANNEL = 6
local PWM_THRESHOLD = 1500    -- Пороговое значение ШИМ: > 1500 считается включенным положением
local CHECK_INTERVAL_MS = 100 -- Период опроса тумблера: 100 мс (10 Гц)

-- Флаг предыдущего состояния переключателя (для защиты от повторной отправки)
local switch_was_active = false

-- Вывод уведомления об успешной инициализации скрипта в консоль GCS
gcs:send_text(6, string.format("[%s] Script initialized on RC CH %d (AUX2)", SCRIPT_NAME, AUX_CHANNEL))

-- Основная функция цикла обновления
function update()
    -- Считываем текущее значение длительности импульса в микросекундах
    local pwm = rc:get_pwm(AUX_CHANNEL)

    -- Проверяем, что канал возвращает валидное значение (не nil)
    if pwm then
        local switch_is_active = (pwm > PWM_THRESHOLD)

        -- Детектирование переднего фронта: тумблер перевели из выключенного во включенное состояние
        if switch_is_active and not switch_was_active then
            -- Отправляем сообщение "hello world" с уровнем INFO (6)
            gcs:send_text(6, "hello world (AUX2 activated)")
        end

        -- Обновляем сохраненное состояние для следующей итерации
        switch_was_active = switch_is_active
    end

    -- Возвращаем указатель на функцию и интервал времени до следующего вызова
    return update, CHECK_INTERVAL_MS
end

-- Первый вызов функции запускает периодический планировщик
return update()
```

Сохраните файл (`Ctrl + S`).

### Этап 5 — Эмуляция переключения AUX2 и тестирование скрипта

#### Способ 1: Эмуляция аппаратуры управления через консоль MAVProxy 

В консоли MAVProxy доступна встроенная команда `rc <channel_number> <pwm_value>`.

1. Проверьте текущее значение каналов:
   Введите в консоль MAVProxy:
   ```mavproxy
   rc status
   ```
   Консоль вернет текущее значение ШИМ по каналам (обычно `0`).

2. **Включение AUX2 (канал RC6, перевод тумблера вверх):**
   Установите значение ШИМ для 6-го канала равным `2000` мкс:
   ```mavproxy
   rc 6 2000
   ```

3. **Анализ результата:**
   * В консоли MAVProxy появится строка:
     ```text
     AP: hello world (AUX2 activated)
     ```
   * В окне Mission Planner (во вкладке **Messages** и во всплывающей строке сообщений на авиагоризонте) отобразится аналогичное сообщение.
   * Обратите внимание: сообщение вывелось один раз, несмотря на то, что функция `update()` вызывается каждые 100 мс.

4. **Проверка фильтрации повторов:**
   Подождите 5–10 секунд. Новых сообщений в консоли быть не должно.

5. **Возврат тумблера в выключенное положение:**
   ```mavproxy
   rc 6 1000
   ```
   Новые сообщения не отправляются.

6. **Повторное переключение:**
   Снова переведите тумблер в активное положение:
   ```mavproxy
   rc 6 2000
   ```
   В консоли снова появится строка:
   ```text
   AP: hello world (AUX2 activated)
   ```

#### Способ 2: Управление через интерфейс Mission Planner
Вы также можете управлять симулируемыми каналами через Mission Planner:
* Перейдите во вкладку **Actions** под авиагоризонтом;
* В выпадающем списке действий выберите команду `Set RC`;
* Задайте номер канала (**6**) и значение ШИМ (**2000**) и нажмите кнопку подтверждения действия;
* Убедитесь, что сообщение зафиксировано во вкладке **Messages**.

#### Часть 1. Подключение реальной аппаратуры радиоуправления по USB к Mission Planner

Вместо консольных команд `rc 6 ...` необходимо реализовать прямое управление каналом AUX2 с помощью физического пульта (радиоаппаратуры):

1. **Подключение пульта к ПК:**
   * Подключите аппаратуру радиоуправления к компьютеру через USB-кабель.
   * На пульте выберите режим **USB Joystick (HID)**.
   * Проверьте обнаружение устройства в Linux с помощью команды в терминале:
     ```bash
     ls /dev/input/js*
     ```
     Должно появиться устройство (например, `/dev/input/js0`).

2. **Настройка канала AUX2 на аппаратуре:**
   * В меню модели на аппаратуре перейдите на страницу **MIXER** (Микшер).
   * Назначьте на **Канал 6 (CH6)** физический тумблер пульта: двухпозиционный (например, тумблер `SA`/`SF`) или трехпозиционный (`SB`/`SC`).

3. **Настройка джойстика в Mission Planner:**
   * Откройте Mission Planner (подключенный к симулятору по UDP 14550).
   * Перейдите в раздел **CONFIG/TUNING** -> **Joystick**.
   * В выпадающем списке выберите обнаруженный пульт управления.
   * Выполните калибровку осей или настройте сопоставление каналов: убедитесь, что тумблер на аппаратуре изменяет значение канала 6 (AUX2).
   * Нажмите кнопку **Enable** (Активировать джойстик).
   * Откройте экран **DATA** -> **Tuning** или окно калибровки радио **Mandatory Hardware** -> **Radio Calibration** и убедитесь, что при щелканье тумблером на физическом пульте шкала 6-го канала в Mission Planner изменяет значение от 1000 до 2000 мкс.

4. **Проверка работы скрипта от аппаратуры:**
   * Перещелкните назначенный тумблер на пульте;
   * Убедитесь, что симулируемый ArduPilot получает сигнал по каналу 6 через MAVLink RC Overrides и скрипт выводит уведомление `hello world (AUX2 activated)`.

#### Часть 2. Модификация Lua-скрипта

Модифицируйте скрипт `hello_aux2.lua` для решения следующих прикладных задач:

1. **Поддержка трехпозиционного тумблера AUX2:**
   Настройте на пульте трехпозиционный тумблер для 6-го канала (`CH6`) и доработайте логику скрипта:
   * **Положение 1 (LOW, PWM < 1300 мкс):** переключатель выключен. При переводе в это положение выводится сообщение: `[AUX2] System: STANDBY`;
   * **Положение 2 (MID, 1300 <= PWM <= 1700 мкс):** среднее положение. При переводе выводится: `[AUX2] System: READY`;
   * **Положение 3 (HIGH, PWM > 1700 мкс):** активное положение. При переводе выводится сообщение: `hello world! (AUX2 ACTIVE)`.
   * *Требование:* Каждое сообщение должно выводиться **строго один раз** при входе в соответствующее положение без спама в цикле!

2. **Интеграция телеметрии в сообщение:**
   Добавьте к выводимому сообщению в положении HIGH вывод текущего полетного режима летательного аппарата или текущей высоты (используя функции `ahrs:get_relative_position_NED_home()` или `baro:get_altitude()`). 
   *Пример формата вывода:* `hello world! (AUX2 ACTIVE) | Alt: 12.4m, Mode: STABILIZE`.
